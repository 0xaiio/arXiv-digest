# FAQ（概念型）

这里回答"该不该这样用 / 为什么这样设计"。**报错了怎么办**请看
[故障排查](../operations/troubleshooting.md)；名词释义看[术语表](glossary.md)。

---

## 一、定位与边界

### 它是给谁用的？

想在**每天几十到几百篇新论文**里，用 5 分钟锁定"今天该读的 10 篇"的研究者。
它假设你有相对稳定的研究方向、愿意花 10 分钟配一次画像，然后长期用。

不适合：想做全领域趋势分析、想替代文献管理工具（Zotero）、想多人协作。

### 和 arXiv-sanity / papers with code 有什么区别？

| 维度 | 本项目 | 在线推荐服务 |
| --- | --- | --- |
| 画像 | 完全本地，你写的关键词/人名/系统名，可精确到主题权重 | 多为隐式协同过滤 |
| 数据 | 全在本地 JSON/SQLite，可审计、可手改 | 在对方服务器 |
| 反馈 | 每次点击立即改权重，当场重排 | 通常延迟生效 |
| 扩展 | 全部代码可改，加信号只改一个函数 | 不可改 |

### 能用于非计算机领域吗？

可以——它是**通用关键词打分**，而且分类本身已经完全数据化（官方 155 个分类任选），
不存在任何 cs 专属逻辑：

1. `/profile` →「🗂 arXiv 类别」选目标分类（`math.AC`、`q-bio.NC`、`econ.EM` 都在官方表里）；
2. `interests.topics` 写该领域的主题关键词；
3. `expand_categories` **留空即可**：扩展池会自动取同 archive 的兄弟分类
   （选 `math.AC` → 其余 `math.*`）。

历史版本里唯一写死领域的地方（`config.example.json` 的四个 cs 分类、`page.html` 的
`arXiv cs.*` 标题、`fetch_expand.py` 的 cs 兜底列表）都已移除，见
[arXiv 类别](../reference/categories.md)。

## 二、隐私与数据

### 会把我读什么上传到任何地方吗？

不会。整个系统只有两类出站请求：

1. 抓取论文元数据（arXiv API / RSS）；
2. 下载 PDF（arxiv.org）。

你的画像、收藏、Downvote、阅读行为**只写本地文件**。没有账号、没有遥测。
唯一的例外是**你自己启用**的视频投稿（`bili_upload.py`），那会把视频与标题发到 B 站。

### 为什么 `config.json` / `interests.json` 不进仓库？

它们含**本机路径与个人研究画像**。仓库是公开的，因此只提交模板
（`*.example.json`）与自愿公开的数据包（`presets/<名字>/`）。这样别人 clone 下来是干净的，
你也随时能 `tools/preset.py export` 分享一份。

### 新用户第一次打开会不会看到作者的研究方向？

不会，而且这是**结构保证**而不只是"记得别提交"：

- 模板 `interests.example.json` 的 `topics` / `owners` / `people` 都是空数组，
  `config.example.json` 的 `categories` 也是空数组；
- `presets/` 里的数据包**运行时完全不参与**：任何页面都不解析它的内容，
  只有 `--preset`、`tools/preset.py import` 或界面上的「导入」才会写进本机；
- `/profile` 的「📦 数据包」面板只显示**包名 + 文件清单 + 体积**，不显示标题、描述、
  类别、主题与人名——那句描述往往就是作者的类别选择与研究方向。

规则与取舍见[私人数据隔离](../architecture/data-isolation.md)。

### 换电脑怎么迁移？

一条命令就够了（旧机器上）：

```bash
python tools/preset.py export myown --with-usage --with-notes
```

把 `presets/myown/` 整个目录拷到新机器（放进 `presets/`），然后：

```bash
python run_daily.py --preset myown
```

`download_dir` 会被 `export` 中性化成 `papers/`，**导入后记得在 `/profile` 里改成自己的目录**；
`library.downloads[].path` 也被裁成文件名，换机器后需要重新下载（收藏记录本身会保留）。

手工拷也可以，但要自己带全：

| 要带走的 | 不带也行 |
| --- | --- |
| `config.json`、`interests.json`（画像种子） | `raw*.json`（重新抓一次即可） |
| `output/library.json`（收藏/下载/Downvote） | `papers_index.json`（下次重算生成） |
| `output/profile_state.json`（学到的权重） | 各种 `*.html`（重渲染） |
| `output/archive.db` + `output/archive/`（历史） | `netroute.json`（换网络自动重探） |

## 三、设计与行为

### 为什么 Downvote 后卡片不消失，而是变灰划线？

因为"消失"会让**误点无法撤销**——你连自己点过哪篇都看不到。现在的行为：

- 变灰 + 标题删除线，**留在原位次**（`data-dvpos` 记录点击时的位次）；
- 再点一次即恢复；
- 但它的分数已被 -12，所以下一次重算会自然沉下去。

三个模块（为你推荐 / 兴趣扩展 / 分类详解）表现完全一致，因为共用同一个 `setDv()` 与一组 CSS。

### 为什么推荐只有十几篇？

`top_recommend` 默认 14、`top_expand` 默认 10。推荐是"决策辅助"，不是"索引"——
一屏能看完才有用。想看全量去「📖 分类详解」，或用 `config.top_recommend` 调大。

### 为什么简介与摘要译文要手工补？

自动翻译的摘要对**判断该不该读**几乎没帮助（术语错译会误导），而错译的成本由你承担。
项目选择"缺就空着"，并提供 `tools/gen_pending.py` 导出待补清单（`--en` 查英文简介、
`--abs` 查摘要译文），你可以自己写、也可以让助手写。两个文件都是纯文本，人工可审。

唯一的例外是英文简介：没写 `en` 时，页面会取摘要开头若干**完整句子**兜底——
那本来就是"摘要核心内容"的英文版，不构成误译风险。

### 为什么必须有本地服务？纯静态不行吗？

静态 HTML 能做阅读与筛选，但**不能写**：收藏、下载、Downvote 都要落在
`library.json` / `profile_state.json` 上。浏览器不能直接写本地文件，所以需要一个本地进程。

顺带的好处：页面用 `file://` 打开也能交互（服务在跑时），见
[服务运行时](../architecture/server-runtime.md) §5。

### 跑测试会动到我自己的数据吗？

不会。每个用例都在 `tmp_pytest/<tag>-<随机后缀>/` 下的独立沙箱里跑（`tempfile.mkdtemp` 建目录、
从不删除——本机沙箱会拦截删除），
`tests/conftest.py` 把 10 个模块的路径常量全部重定向过去，并**断言**没有任何一个还指向
真实目录；另有一条测试专门扫描源码，防止新模块绕过这层隔离。

唯一会读写真实 `output/` 的是 `tools/*_check.py`（发布前的黑盒验收，例如真点一次下载），
它们被刻意设计成「只读或幂等」，但你仍应在跑之前知道这一点。

详见[测试与回归](../contributing/testing.md)。

### 为什么用 JSON 文件存收藏，而不是数据库？

| 考虑 | JSON | SQLite |
| --- | --- | --- |
| 数据量 | 千级条目毫无压力（当前 ~180 KB） | 过度设计 |
| 可读性 | 打开就能看、能改、能 diff | 需要工具 |
| 迁移 | 拷一个文件 | 拷一个文件 + 版本兼容 |
| 并发 | 一把锁 + 原子替换足够 | 需要事务 |

真正需要事务的是**归档**（`archive.db`），那里用了 SQLite——按需分级，不搞统一。

### 会不会把 arXiv 打挂 / 被封？

不会。默认每个分类 80 条、扩展全局 600 条，一天一次；API 限流时自动降级 RSS 而不是反复重试；
批量下载并发上限 3。请保持这个量级，不要把它改成"每十分钟抓一次全站"。

## 四、使用建议

### 第一次用，画像应该写多细？

3–6 个主题、每个 6–15 个关键词、5–20 位熟悉作者。**不要**追求"完整覆盖自己的研究领域"——
画像越精确，漏掉的越多；留白交给「兴趣扩展」区。

### 用多久能"学准"？

取决于点击量。前 20–30 次收藏/下载主要建立方向感；100 次之后主题倍率会明显分化
（`python profile.py` 可看）。想要稳定效果，建议每天至少点 3–5 次。

### 一天跑几次合适？

一次。arXiv 每工作日 20:00 ET 公告一次（北京时间约次日 08:00），多跑没有新内容，
只会增加抓取次数。周一批次覆盖周末，所以周一通常最多。

### 用不用每天看「分类详解」？

不必。它的用途是"抽查"——当你怀疑推荐漏掉了什么时，翻一遍本周的分类详解。
日常只看推荐 + 扩展两屏就够。

### 我想同时维护两份画像（如两个课题）怎么办？

目前不支持多画像。可行的变通：把第二课题做成**几个相邻分类 + 独立主题**，靠
`expand_categories` 单独成区；或者在另一个目录 clone 第二份实例（数据完全隔离）。
