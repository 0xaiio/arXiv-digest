# 调优画像

目标：让"为你推荐"更贴近你真正关心的东西。本文只讲**怎么调、调了会怎样**；
字段的精确含义见 [interests.json 参考](../reference/interests.md)，公式见
[排序与学习算法](../architecture/ranking.md)。

---

## 一、先判断问题出在哪

调之前先分清三类症状，它们的解法完全不同：

| 症状 | 大概率原因 | 去哪一节 |
| --- | --- | --- |
| 推荐区**空的**，或只有 1–2 篇 | 画像太薄：没有任何论文够到 7 分阈值 | §2 起步配置 |
| 有推荐，但**方向不对**（全是隔壁领域） | 主题关键词太泛，或 `categories` 本身不对 | §3 主题与关键词 |
| 方向对，但**排名不合理**（该上来的没上来） | 权重/熟悉作者/代表系统没配好 | §4–§6 |
| 前几天正常，**突然一片低分** | 画像被行为带偏（负向学习把主方向打到下限） | §7 画像漂移 |

一条命令看清当前状态：

```bash
python profile.py
```

输出主题倍率、关键词两端极值、被 Downvote 的论文列表。这是排查"推荐突然变差"最快的手段。

## 二、起步配置：三条最小路径

**A. 从分类开始（最省事）**

只改 `config.json` 的 `categories`，画像留空也能出推荐——此时走的是**兜底模式**：
严格阈值一篇都不达标时，按分数取前 N 并在卡片上注明"画像尚未命中，先按分数兜底"。
适合"先跑起来看看"。

**B. 从主题开始（推荐）**

在 `/profile` 里设 3–6 个主题，每个主题 6–15 个关键词。判断关键词好坏的经验法则：

- **好关键词**：`linearizability`、`isolation level`、`CRDT`、`refinement type`、`Byzantine broadcast`——
  出现在标题里就基本锁定方向；
- **坏关键词**：`distributed`、`data`、`model`、`system`——几乎所有论文都有，等于没筛；
- 短语比单词好：`"shared memory"` 比 `shared` 准得多。

**C. 从人开始（见效最快）**

把 5–20 位你追的研究者放进 `people`（或在 `/profile` 的"画像主来源"里新增并勾选联动）。
每命中一位，该篇 +10 分——这是单项权重最高的一条信号。适合"跟着人读"的习惯。

## 三、主题与关键词

每个主题有两个可调项：`weight`（种子权重，默认 1.0）与 `keywords`。

一次点击的贡献（详见[公式](../architecture/ranking.md)）：

```
主题原始分 = 4 × min(标题命中关键词数, 4) + 0.8 × min(摘要命中数, 15)
贡献       = 主题原始分 × 主题权重（种子 × 行为学习倍率）
```

调节建议：

| 想要 | 做法 | 副作用 |
| --- | --- | --- |
| 某个方向更靠前 | 把该主题 `weight` 提到 1.3–2.0 | 过高（>2.5）会挤掉其它方向 |
| 某方向只是"顺带看看" | `weight` 降到 0.5–0.7，或干脆只放进 `expand_categories` | 低于 0.5 基本不会进推荐区 |
| 同一方向的不同侧面 | 拆成两个主题、各自关键词更精确 | 主题数 >8 后边际收益下降 |

> **顺序不变式**：`topics` 的先后顺序 = 前端重排时的权重索引。代码里由
> `customize.effective_topics()` 统一拼接（原主题 + 自定义主题「我的来源关注」），
> 不要在别处手工重排，否则页面上的实时重排会拿错权重。

## 四、降权词（`negative`）

用于"这个词一定与我无关"的热点词，例如某个突然刷屏但你完全不关心的子领域。

```
扣分 = weight × 3 × min(命中数, 4)，weight 默认 -1.0
```

注意它只**降权不排除**：命中降权词的论文仍然出现在「分类详解」里，只是很难挤进推荐区。
要彻底不看，靠 Downvote 单篇（-12）而不是降权词。

## 五、兴趣来源（把网页/论文/文档变成画像）

`/profile` →「兴趣来源」支持三种输入：

| 类型 | 输入 | 解析方式 |
| --- | --- | --- |
| `link` | 个人主页、实验室页、项目页 | 抓 HTML，抽重复出现（≥2 次）的人名与专业实词 |
| `paper` | arXiv 短号或链接 | 取标题/摘要；**作者直接采信**（论文作者是确定信号） |
| `doc` | 本地 `.txt/.md/.html/.csv/.json/.pdf` | 同 `link`，但读本地文件 |

解析结果分三路进入画像：

1. **人名** → 追加进"熟悉研究者"（每命中一篇 +10）；
2. **专业实词** → 汇总成自定义主题「**我的来源关注**」（权重固定 0.6）；
3. **命中主题** → 记录该来源与哪些已有主题相关（仅展示，不额外加分）。

要点：

- 上限：人名 60 个、关键词 60 个、命中主题 10 个；
- 与已有 `people` / 主题关键词重复的会被自动去重；
- 「屏蔽关键词」只是把这个词从来源增量里剔除（并触发重建），不影响你手写的主题关键词；
- 删除来源会撤销它带来的全部增量——这也是它比手改 JSON 更安全的地方。

## 六、用反馈微调（让系统自己学）

`profile.apply_event()` 按行为更新画像，强度可在 `interests.json` 的 `behavior.actions` 里调：

| 行为 | 默认强度 | 学习方向 |
| --- | --- | --- |
| 下载 | 1.3 | 最强正向：下载基本等于"我要读" |
| 收藏 | 1.0 | 强正向 |
| 打开 PDF | 0.55 | 中弱正向 |
| 展开 Abstract (EN) / (CH) | 0.3 | 弱正向（误点代价小）；两个按钮都记 `action=abstract` |
| 取消收藏 | -0.7 | 反向（但比收藏弱，避免抖动手滑） |
| Downvote / 撤销 | -1.6 / 0.9 | **只作用于单篇 -12**，不进入全局学习 |

学习率 `lr_topic` / `lr_keyword`：代码默认 0.06 / 0.05，作者预设里用 0.15 / 0.12（学得更快、
也更容易被几次误点带偏）。想稳一点就调小，想快一点就调大，改完重跑一次 `recommend.py` 生效。

**为什么负向学习默认关闭**（`learn_neg_topics` / `learn_neg_keywords` = false）：
推荐得越多的主题，被 Downvote 的绝对次数也越多。若让 Downvote 扣主题分，系统会把自己的主打方向
一路打到 0.25 下限——真实踩过的坑，症状是"某天开始推荐数归零"。
Downvote 的语义是"这篇不要"，用单篇 -12 已经足够精确。完整案例见
[排序与学习算法](../architecture/ranking.md) §5。

## 七、画像漂移：症状与修复

**判据**：`output/scores.json` 里全池 Top10 分数仍然正常（如 30+），但**当期**新增全部低分
→ 说明画像坏了，不是内容差、也不是抓取坏了。

**自查**：

```bash
python profile.py            # 主题倍率是否触底 0.25？关键词是否出现 -3 以下？
```

**修复（保留你的显式意图）**：

1. 备份 `output/profile_state.json`；
2. 删除其中的**负向**关键词条目（保留正向的）；
3. 把 `topic_mult` 全部归 1.0；
4. **保留** `paper_bonus` 里所有 -12 惩罚——那是"这篇不要再推"的精确表达；
5. 重跑 `python recommend.py && python build_report.py`。

## 八、调参之外的三件事

- **别频繁重抓**：`categories` 改完抓一次就够，`--skip-fetch` 可复用已有数据秒级重算；
- **别把 Downvote 当主题开关**：方向级偏好写在主题权重里；
- **改完必须让页面重算**：画像改动只影响下一次 `recommend.py`；摘要页是静态文件，
  点「↻ 重算推荐」或重跑 `build_report.py`。`/profile` 页本身是实时读文件的，不用重启。
